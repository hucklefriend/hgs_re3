# 公開グリッドネットワークUI

## 対象

公開画面は、Bladeによるサーバーサイドレンダリングと`PublicSiteApp`によるページ単位の初期化で構成する。管理画面は独立したレイアウトとアセットを使用し、このUIの対象外とする。

実装の主な配置は次のとおり。

- 公開レイアウト: `resources/views/layout.blade.php`
- ライフサイクル: `resources/ts/site/public-site-app.ts`
- グリッドと背景信号: `resources/ts/site/grid/`
- ページ遷移演出: `resources/ts/site/navigation/`
- ページ固有制御: `resources/ts/site/pages/`
- デザイントークンと共通CSS: `resources/css/site/`

## ページ構成

公開レイアウトのルートには`data-public-app`と`data-page-kind`を設定する。`PublicSiteApp`は公開ルートが存在する場合だけ起動し、文書ロードごとにグリッド、遷移演出、ページコントローラ、ページ内コンポーネントを初期化する。

専用ページは`site-content`セクションでページ全体を定義する。その他のページはレイアウトが`.site-standard-page`へまとめ、見出し、本文、関連セクションを共通グリッド規則で表示する。

新しいページでは、内容に合った`article`、`section`、`nav`、見出し階層を使い、ページ固有の絶対配置を増やさない。

## グリッド

グリッド寸法、色、余白、モーション時間は`resources/css/site/tokens.css`のカスタムプロパティを参照する。`GridMetrics`がCSSと同じ値から文書座標とグリッド交点を計算し、背景信号と遷移演出の位置を揃える。

`GridPlaneController`は初期表示、リサイズ、文書高の変化を監視する。購読を追加した場合は、ページ離脱時に必ず解除する。

## 視覚的な整列

背景グリッドは装飾だけではなく、公開画面のレイアウト基準として扱う。ヘッダー、パネル、メニューなどの固定的なUI領域は、上端・下端および主要な区切り線を背景の水平グリッド線へ揃える。

- 高さや上下余白には原則として`--site-grid-row-size`またはその整数倍・意図の明確な分割値を使う。
- ヘッダーやパネルの境界線は、近接する背景グリッド線と重なって一続きに見える位置へ置く。
- 固定高にすると本文の欠落や重なりが起きる可変コンテンツでは、内容を優先する。上端をグリッドへ揃え、下端は次のグリッド線へ着地する余白を確保する。
- デスクトップだけでなくモバイルでも、グリッド寸法の変更後に境界位置と横スクロールの有無を確認する。
- 既存コンポーネントを別の文脈へ流用する場合は、情報階層に合う密度へ調整する。補助メニューへ主要パネルと同じ大きさ・見出し階層をそのまま持ち込まない。

接続線と接続点は、リンク先へ信号が流れることを示す一つの記号として扱う。両者の中心軸を一致させたうえで、隣接するリンクテキストの視覚的な縦中央へ揃える。

- 接続点の円と、そこから伸びる接続線の中心軸をずらさない。
- 配置基準はリンクボックス全体の中央ではなく、表示されているテキストまたはテキストブロックの視覚的な中央とする。
- リンクの高さや上下余白がテキストの行ボックスより大きい場合は、テキストと補助件数を`.site-connection-label`で包み、接続端子をリンク全体ではなくラベルの`line-height: 1`の行ボックスに対して配置する。
- 端子の基準軸は`.site-connection-label`の行ボックス中央とし、小さい日本語グリフの視覚中心が行ボックス中央より下へ見える差を`--site-connection-text-optical-offset`の正方向フォント相対値で共通補正する。モノスペース書体は`.site-connection-label--mono`で専用メトリクスを選び、書体差をページ座標のpx補正として扱わない。
- `ConnectionTerminalController`が計測した配置元の中央は`--site-terminal-owner-y`へ設定する。コンポーネント固有の配置軸が必要な場合だけ`--site-terminal-y`で上書きし、共通の光学補正とは分離する。
- 端子の中央移動には個別の`translate`、縮小には`--site-terminal-scale`経由の個別の`scale`を使う。`transform: translateY(...)`と`scale`を併用すると移動量まで縮小されるため、組み合わせない。
- JavaScriptなしでも必要な端子はBladeで出力する。JavaScriptは子孫端子を再利用し、1リンクに複数の端子を生成しない。
- 単一行と複数行、通常時とフォーカス時で中心軸が変わらないことを確認する。
- 接続点の位置を変更した場合は、ページ遷移演出が取得する端子座標にも同じDOM位置が反映される構造を維持する。

## 背景信号

`AmbientSignalController`は画面端のグリッド交点から信号を生成する。経路は水平・垂直の線分だけで構成し、主進行方向へ逆走しない。

- デスクトップとタブレットは最大4個、モバイルは最大2個まで同時表示する。
- タブが非表示の間は生成を停止する。
- `prefers-reduced-motion: reduce`では生成しない。
- リサイズや文書高変更時は古い座標の信号を破棄する。
- 終了、状態変更、ページ離脱時にDOM、タイマー、AnimationFrameを破棄する。

## ページ遷移

同一オリジンの通常GETリンクは、必要に応じて接続端子からヘッダーへ信号を引き渡す演出を行った後、ブラウザーの文書遷移を開始する。

ハッシュ、外部リンク、ダウンロード、別タブ、修飾キー付きクリックはブラウザー標準動作を維持する。戻る・進むでページが復元された場合は、残っている表示状態を`pageshow`で初期化する。

低減モーション時は接続演出を省略し、操作結果や情報量は変えない。演出で例外が発生しても、リンク遷移自体は必ず継続させる。

## ページ固有UI

トップ、ラインナップ、タイトル詳細などページ全体に固有の制御は`PageController`として`resources/ts/site/pages/`へ置く。タブ、セクション追従、スクロール監視などを追加した場合は`dispose()`でイベントとObserverを解除する。

フォーム、レビュー、フォロー、リアクションなど再利用可能な機能は`resources/ts/components/`へ置き、`ComponentManager`から初期化する。

## 確認項目

- `npx tsc --noEmit`
- `npm run test:unit`
- `npm run build`
- ヘッダー、パネル、主要な区切り線が背景の水平グリッド線と揃っていること
- 接続線と接続点の中心軸が一致し、隣接テキストの視覚的な縦中央にあること
- デスクトップとモバイルで横スクロールが発生しないこと
- 低減モーションで情報や操作が欠落しないこと
- JavaScript無効時も主要本文、リンク、通常フォームが利用できること
- 管理画面に`data-public-app`や公開アセットが混入しないこと
