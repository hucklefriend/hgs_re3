# 公開画面の文言規約

## 目的

HGN の公開画面では、データベースとして必要な情報の明瞭さを保ちながら、空状態や未確認の情報をサバイバルホラーゲームの状況説明テキストのように表現する。

特定作品の台詞を再現するのではなく、「周囲を調べた結果」「記録を確認した結果」「手がかりが見つからない状況」を淡々と伝える、このサイト固有の文章にする。

## 世界観を適用する文言

次のような、情報がないことを示す補助的な文章に適用する。

- 一覧、検索結果、タイムラインなどの空状態
- あらすじ、画像、関連商品などの未登録状態
- 評価、レビュー、活動などの記録がない状態
- 通信や更新情報が届いていない状態

文言は、対象と状況が一読で分かる一文にする。雰囲気だけを優先して、何がないのか分からない文章にはしない。

```text
この作品について、詳しいことはまだわからない。
この作品について書かれた記録は、まだないようだ。
この作品を入手する手がかりは、まだ見つかっていないようだ。
新しい通信は、まだ届いていないようだ。
あたりを調べたが、条件に合う作品は見つからないようだ。
```

## 書き方

- 観察者が状況を確認しているような、短く静かな文章にする。
- 原則として常体を使い、「〜ようだ」「〜ない」「〜わからない」などで結ぶ。
- 一文で完結させ、感嘆符、過剰な恐怖表現、長い演出文は避ける。
- 「データがありません」「登録されていません」だけの管理画面風の表現を、公開画面の空状態へそのまま使わない。
- 対象となる名詞を残す。例えば検索結果なら「作品」、レビューなら「記録」、販売情報なら「入手先」や「手がかり」を含める。
- 同じ画面や同種のコンポーネント内で、常体と敬体を混在させない。
- 特定のゲーム、作品、キャラクターを連想させる固有名詞や台詞の直接的な引用はしない。

## 世界観を適用しない文言

操作や安全性に関わる文言は、正確さと即時理解を優先し、状況説明風にしない。

- ボタン、リンク、ナビゲーション、フォーム項目のラベル
- 入力方法や次に行う操作の案内
- バリデーションエラー、認証エラー、権限不足、閲覧制限
- 削除済み、非表示、保存成功、送信失敗などの状態通知
- 年齢制限、課金、購入、アフィリエイト、法的事項に関する説明
- 404 など、利用者が原因や対処を判断する必要があるエラー
- `aria-label`、代替テキストなどのアクセシビリティ用文言

例えば、空状態の本文は「この作品の恐怖については、まだ誰も語っていないようだ。」としても、その直後の操作リンクは「怖さを記録する」のように具体的に書く。

## 実装時の確認

公開画面の文言を追加・変更した場合は、次を確認する。

1. 情報がない対象を文章から判別できるか。
2. 操作文言や重要な通知まで曖昧な表現にしていないか。
3. 既存の同種画面と語尾や温度感が揃っているか。
4. 特定作品の台詞をそのまま引用していないか。
5. Blade を変更した場合は、規定の `umask 0002` を設定してビューキャッシュを生成できるか。
