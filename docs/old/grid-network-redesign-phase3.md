# グリッドネットワークデザイン Phase 3 実施記録

## 1. 実施結果

2026-08-14 に公開画面の共通グリッドへ背景信号を追加した。信号はグリッド端の交点から発生し、水平・垂直の線分だけを高速移動して反対側の端で消える。経路の途中では最大2回まで直角に曲がるが、最初に選んだ主進行方向へ逆走しない。

管理画面の Blade、コントローラー、ルート、アセットには変更を加えていない。

## 2. 経路生成

`resources/ts/site/grid/ambient-signal-route-planner.ts` に DOM 非依存の `AmbientSignalRoutePlanner` を追加した。

- 右、左、下、上の4方向を主進行方向として扱う。
- 主進行軸は開始端から終了端まで単調増加または単調減少する。
- 各区間は水平または垂直で、方向転換はグリッド交点でのみ行う。
- 主進行軸の最小線分長は2セル、直交方向の移動は最大3セルとする。
- 短い経路では曲折数を自動的に減らし、ゼロ長区間や細かな往復を作らない。

単体テストでは4方向すべてについて主進行軸の非反転、直交線分、グリッド境界、短い経路での曲折制限を検証する。

## 3. 発生と描画

`AmbientSignalController` がランダムな方向、開始交点、速度、曲折数を選び、`AmbientSignal` が1個の信号を `requestAnimationFrame` で描画する。

| 項目 | 設定 |
|---|---|
| 発生間隔 | 650〜1800ms |
| 移動速度 | 440〜720px/秒 |
| 曲折数 | 0〜2回 |
| デスクトップ・タブレット同時数 | 最大4個 |
| モバイル同時数 | 最大2個 |

信号は小さな発光ノードと進行方向後方の短い残光で表現する。座標は `GridMetrics.gridToDocument()` で文書座標へ変換し、共通グリッドと同じ原点、セル幅、行高を利用する。縦方向の経路は文書末端を越える最初の交点まで進ませ、グリッド面のクリップ境界で自然に消える。

## 4. ライフサイクルと動きの設定

- `prefers-reduced-motion: reduce` では信号を生成しない。
- タブが非表示になると、発生タイマーと表示中の信号を破棄する。
- タブが再表示されたときは新しい経路で発生を再開する。
- リサイズや文書高変更で `GridMetrics` が更新された場合、旧座標の信号を破棄して再生成する。
- 信号が端へ到達すると自身の AnimationFrame と DOM 要素を破棄し、Controller の管理集合から外れる。
- 公開画面の `pagehide` では発生タイマー、全信号、購読リスナーを破棄する。

`MotionPreference` と `GridPlaneController` には購読 API を追加し、背景信号側が表示状態や実測グリッドの変更へ追従できるようにした。

## 5. 検証結果

| 検証 | 結果 |
|---|---|
| `npm run test:unit` | 成功。2 files / 13 tests |
| `npx tsc --noEmit` | 成功 |
| `npm run build` | 成功。57 modules、CSS 59.56 kB、JS 116.85 kB |
| `php artisan view:cache` | 成功 |
| 公開Chromium | `/` が200、JavaScriptエラーなし、`data-page-ready=true` |
| デスクトップ同時数 | 約15秒の観測で最大4個。上限4個以内 |
| モバイル同時数 | 375px幅で1個。上限2個以内 |
| グリッド整合 | 観測した全信号でXまたはY座標が常にグリッド線と一致 |
| 低減モーション | 設定切り替え後に信号数0、既存信号も残留なし |
| 表示状態変更 | `visibilitychange` の非表示状態で信号数0、再表示後に発生再開 |
| ライブリサイズ | 1440pxから375pxへの変更後、旧信号を破棄し4列経路で再開 |

ヘッドレス Chromium は別ページへフォーカスを移しても `document.hidden` が変わらないため、表示状態を切り替えて `visibilitychange` を発火し、既存 `MotionPreference` の変更通知から発生停止、全信号破棄、再表示後の再開までを確認した。
