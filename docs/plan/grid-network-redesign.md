# グリッドネットワークデザイン移行計画

## 1. 目的

公開画面の現行ツリー型デザインと Ajax 画面遷移を廃止し、`public/new_design2` で検討したグリッドネットワークデザインへ全面的に移行する。

実装は Blade によるサーバーサイドレンダリングと TypeScript を組み合わせ、リンク遷移は通常のドキュメント遷移とする。クリック時の接続アニメーションや遷移先の出現演出は維持するが、次ページの HTML を `fetch` して部分置換する仕組みは持たない。

管理画面は現在のデザインと実装をそのまま維持し、今回の変更対象から除外する。

## 2. 今回の基本方針

- 公開画面のみを新デザインへ移行する。
- Laravel のルーティング、コントローラー、認証、データ取得などのサーバー側機能は可能な限り維持する。
- 公開画面の Blade は通常のページ全体を返す構成にする。
- ページ遷移の直前に演出を行い、終了後は `window.location.assign()` などによる通常遷移を行う。
- Ajax ナビゲーション、History API による擬似遷移、現在ノードの差し替え、ツリー深度管理は廃止する。
- `public/new_design2` は見た目と挙動の参照用モックとして扱い、JavaScript をそのまま本体へコピーせず TypeScript で再設計する。
- 既存のフォーム、レビュー、フォロー、リアクションなどのページ内機能は維持する。
- 旧実装は一度に削除せず、新実装への参照切り替えと回帰確認の後に削除する。
- モック自体は公開画面の移行完了まで残し、削除する場合は最終確認後に行う。

## 3. デザインと挙動の要件

### 3.1 共通デザイン

- ページ全体を同一のグリッド平面として扱い、ヘッダーだけを独立したグリッドにしない。
- デスクトップ、タブレット、スマートフォンで列数を切り替える。初期案はそれぞれ 16 列、12 列、4 列とする。
- 黒に近い背景、細いグリッド線、緑色の発光を基本とする。
- ホラー表現は抑え、ゲームのタイトル画面や設定画面に近いネットワーク端末の印象を優先する。
- ロゴ表記は `HORROR GAME` と `NETWORK` の常時二段表示とし、表示上の略称 `HGN` は使用しない。
- ロゴ領域のグリッド左上交点には常設の緑色ノードを配置し、遷移ノードの到着点と一致させる。
- 各コンテンツの端、見出し、接続端子を可能な範囲でグリッド交点またはグリッド線に揃える。

### 3.2 背景信号

- 背景のグリッド線上に、ランダムな間隔で光の玉を出現させる。
- 信号は比較的速く移動し、ページ端へ到達したら消える。
- 途中の交点で直角に曲がる場合がある。
- 出現時に決めた主進行方向は反転させない。例として左から右へ進む信号は、途中で上下へ曲がっても右から左へは戻らない。
- 同時表示数に上限を設け、非表示タブでは停止する。
- `prefers-reduced-motion` が有効な環境では停止または大幅に簡略化する。

### 3.3 リンク遷移

- 通常の同一オリジン GET リンクだけを演出対象にする。
- 外部リンク、ページ内リンク、ダウンロード、別タブ指定、修飾キー付きクリックはブラウザー標準の挙動を優先する。
- クリックされた要素以外を短時間でフェードアウトする。
- 大きな画像やカード全体をリンクにした場合も、リンク本体を粒子化せず、リンクに付属する小さな接続端子を遷移ノードの出発点にする。
- 遷移ノードは現在位置に近いグリッド交点へ吸着し、グリッド線上を直角に移動してロゴ領域の常設ノードへ到達する。
- ノードはビューポート座標ではなくドキュメント座標で移動させる。
- 長いページでは移動ノードが見えるように画面を追従スクロールさせる。
- 演出終了後に通常のページ遷移を行う。タイムアウトや例外が発生しても必ず遷移できるようにする。
- 遷移先では左上から右下へ、暗い状態から徐々に発光する短い到着演出を行う。
- 戻る・進む、BFCache、ハッシュ付き URL、初回直接アクセスでも画面が非表示のまま残らないようにする。

## 4. 管理画面の保護境界

今回の変更では、以下を変更・削除しない。

- `resources/views/admin/**`
- `public/assets/**`
- `public/admin_assets/**`
- `app/Http/Controllers/Admin/**`
- `routes/web.php` 内の管理画面向けルートグループ
- 管理画面が利用する vendor CSS、vendor JavaScript、画像、フォント

現在、管理画面は `resources/views/admin/layout.blade.php` を利用し、公開画面用の Vite エントリーポイントを読み込んでいない。この分離を維持する。

公開画面用の変更では以下を原則とする。

- `resources/views/layout.blade.php` と公開画面の Blade のみを対象にする。
- CSS セレクターは `body` への無制限な指定を避け、`[data-public-app]` など公開画面固有のルート配下へスコープする。
- TypeScript は公開画面のルート要素が存在するときだけ起動する。
- 管理画面のレイアウトへ新しい `@vite` 読み込みを追加しない。
- 各フェーズで公開画面だけでなく管理画面のログイン画面と代表的な一覧画面をスモーク確認する。

## 6. TypeScript クラス設計

### 6.1 起動とライフサイクル

#### `PublicSiteApp`

公開画面の唯一の構成ルート。各コントローラーを生成して起動し、`pagehide` などで破棄する。

- `start(): void`
- `dispose(): void`
- グリッド、背景信号、遷移、到着演出、既存コンポーネントの起動順を管理する。
- グローバルな巨大シングルトンにはせず、`app.ts` から一度だけ生成する。
- `[data-public-app]` がないページでは生成しない。

#### `Disposable`

イベントリスナー、タイマー、`requestAnimationFrame`、`ResizeObserver` を確実に解除するための共通インターフェース。

```ts
interface Disposable {
    dispose(): void;
}
```

#### `MotionPreference`

`prefers-reduced-motion` とタブ表示状態を集約し、アニメーションの実行可否を提供する。

### 6.2 グリッド

#### `GridMetrics`

グリッド計算の唯一の情報源とする純粋クラス。

- 現在の列数、セル幅、行高、原点を保持する。
- CSS カスタムプロパティとグリッド要素の実測値から更新する。
- ドキュメント座標とグリッド座標を相互変換する。
- 任意座標を最寄りの交点へ吸着する。
- ヘッダー到着点やページ端の交点を返す。

#### `GridPlaneController`

DOM 上のグリッド平面と `GridMetrics` を同期する。

- `ResizeObserver` と画面回転・リサイズを監視する。
- ドキュメント高の変化に追従する。
- CSS カスタムプロパティを更新する。
- 背景、ヘッダー、本文が同じ原点を利用する状態を保証する。

### 6.3 背景信号

#### `AmbientSignalRoutePlanner`

開始交点、主進行方向、曲がる回数から経路を生成する純粋クラス。

- 経路は水平・垂直線分だけで構成する。
- 主進行軸の値は単調増加または単調減少とし、逆走を禁止する。
- 直交方向への寄り道後も最終的にはページ端へ到達させる。
- 最小線分長と最大曲折回数を設け、不自然な細かい振動を防ぐ。

#### `AmbientSignalController`

背景信号の発生間隔と同時表示数を管理する。

- ランダムな開始位置、方向、速度、曲折数を決める。
- 同時表示数はデスクトップで最大 4 個程度、モバイルで最大 2 個程度を初期値とする。
- `document.hidden` または低減モーション時は新規発生を停止する。
- ページ離脱時に全信号を破棄する。

#### `AmbientSignal`

1 個の信号ノードを担当する。

- 経路に沿った位置と発光を `requestAnimationFrame` で更新する。
- 端へ到達したら自らを破棄し、Controller へ完了を通知する。
- DOM 要素の追加・削除をこのクラス内に閉じ込める。

### 6.4 ページ遷移

#### `LinkClassifier`

クリックされたリンクが演出対象かを判定する純粋クラス。

- 同一オリジンの通常 GET ページ遷移だけを許可する。
- 外部、`mailto:`、`tel:`、ハッシュのみ、`download`、`target`、修飾キー付き操作を除外する。
- 管理画面 URL は公開画面の遷移演出対象にしない。

#### `ConnectionTerminalController`

リンクに付属する接続端子の配置と状態を管理する。

- Blade で明示された端子を優先する。
- 大きなカードや画像リンクでも一定サイズの端子を使用する。
- レスポンシブ変更後に最寄りのグリッド線・交点へ位置を補正する。
- hover、focus、接続中、無効状態を CSS クラスまたは data 属性で表現する。

#### `HandoffRoutePlanner`

クリックした端子からヘッダーの常設ノードまでの経路を作る純粋クラス。

- 始点を最寄りの交点へ接続する短い区間を作る。
- その後はグリッド線上だけを移動する。
- 終点は `GridMetrics` が返すヘッダー到着交点とする。
- 画面幅、スクロール位置、長いドキュメントでも同じドキュメント座標系を使用する。

#### `HandoffAnimationController`

遷移ノード、軌跡、ヘッダー到着時の発光を描画する。

- Web Animations API または `requestAnimationFrame` を使用する。
- 見た目の速度を経路長に応じて調整し、長いページでも待ち時間が過度に長くならない上限を設ける。
- 完了、キャンセル、タイムアウトを Promise で通知する。

#### `ScrollFollowController`

遷移ノードを追うスクロールを担当する。

- ノードのドキュメント座標から目標スクロール位置を計算する。
- ノードだけが画面に固定されて見える状態を避ける。
- ユーザーの低減モーション設定では即時スクロールまたは追従なしに切り替える。
- 終了後に不要なスクロール処理を停止する。

#### `PageTransitionController`

リンククリックから実際のページ遷移までを状態機械として管理する。

- 多重クリックをロックする。
- 非選択要素のフェードアウトを開始する。
- Handoff と ScrollFollow を並行して実行する。
- 遷移情報を `TransitionStore` に保存する。
- 完了後または安全用タイムアウト後に `window.location.assign()` を実行する。
- HTML の取得や DOM の部分置換は行わない。

#### `TransitionStore`

`sessionStorage` を使用し、遷移元、遷移先、開始時刻などの最小限の情報を次ページへ渡す。

- 有効期限を短くし、古い状態は無視する。
- UI の表示可否に影響する必須データにはしない。

#### `PageArrivalController`

ページ読み込み後の到着演出を担当する。

- 左上から右下へ進むマスクと発光を開始する。
- `TransitionStore` がない直接アクセスでも自然な短縮演出を行う。
- BFCache の `pageshow` で画面状態と遷移ロックをリセットする。
- ハッシュ付き URL では、到着演出を妨げない範囲で目的位置を復元する。
- 例外時も `data-page-ready` を必ず設定して本文を表示する。

### 6.5 ページ内機能

#### `ComponentManager`

既存の `Component` と `resources/ts/components/**` は、Ajax 再描画を前提としない形へ簡略化して再利用する。

- 文書ロード時に一度だけ対象要素を探索して初期化する。
- ページ離脱時に破棄する。
- `data-hgn-scope`、ノード差し替え後の再 hydrate、遅延 CSS の再読込は削除する。
- CSRF、バリデーション、フォーム送信、リアクションなどの機能は維持する。

#### ページ固有コントローラー

- `LineupPageController`: 検索フォームと設定画面風のカテゴリ切り替えを管理する。
- `TitleDetailPageController`: 詳細ページのセクション表示や現在位置を管理する。
- `ConsoleTabs`: キーボード操作可能なタブ UI を提供する。
- `SectionSpy`: スクロール位置と大メニューの選択状態を同期する。
- 単純な情報ページは共通の到着・接続・背景機能だけを利用し、専用クラスを作らない。

## 7. Blade と CSS の方針

### 7.1 Blade

- `resources/views/layout.blade.php` を公開画面専用の新しいシェルへ置き換える。
- ルート要素に `data-public-app`、ページ種別に `data-page-kind` を付与する。
- ヘッダー、パンくず、接続端子、フッターは Blade Component 化する。
- グリッドの列位置は、意味のない大量の空要素ではなく CSS Grid とカスタムプロパティで指定する。
- OGP、CSRF、ログイン状態、サーバーから渡すページデータは維持する。
- フォーム送信は初期段階では通常送信のままとし、必要な既存 API 通信だけをページ内機能として残す。
- 公開画面コントローラーに残る「Ajax のときは部分 HTML または JSON を返す」分岐は、全ページ切り替え後の整理フェーズで削除する。

### 7.2 CSS

- 色、発光、線幅、余白、アニメーション時間を `tokens.css` のカスタムプロパティへ集約する。
- グリッド原点、列数、セル幅はヘッダーと本文で共有する。
- ページ固有 CSS は `site/pages/**` に分ける。
- 公開画面の基礎スタイルは `[data-public-app]` 配下へスコープし、管理画面へ波及させない。
- JavaScript は位置計算と状態変更を担当し、通常状態の見た目は CSS で表現する。
- 接続端子には hover だけでなく `:focus-visible` を用意する。
- アニメーションなしでも情報と操作が欠落しない構造にする。

## 8. 実装フェーズ

全体を 9 フェーズに分ける。各フェーズは単独でビルド可能かつ、通常のページ操作ができる状態で完了させる。

### Phase 0: 現状固定と保護境界の確認

実施記録は [`grid-network-redesign-phase0.md`](./grid-network-redesign-phase0.md) にまとめる。以後のフェーズでは、同ファイルの失敗一覧を既存ベースラインとして差分判定に使用する。

実装内容:

- 公開ルート、公開 Blade、ページ内 TypeScript コンポーネントの対応表を作る。
- 管理画面の保護対象パスを作業チェックリストへ固定する。
- `npm run build`、PHP テスト、既存 Playwright の基準結果を記録する。
- トップ、ラインナップ、タイトル詳細、ログイン、ユーザーページ、管理画面の代表 URL をスモーク対象に決める。

完了条件:

- 移行対象と対象外が一覧化されている。
- 既存の失敗と新規の失敗を区別できる。
- 管理画面の代表ページが現状どおり表示できる。

### Phase 1: 公開画面の新基盤

実施記録は [`grid-network-redesign-phase1.md`](./grid-network-redesign-phase1.md) にまとめる。

実装内容:

- `site` ディレクトリと `PublicSiteApp` を追加する。
- 新しいデザイントークン、共通レイアウト、公開画面ルート属性を追加する。
- `app.ts` を公開画面ルートの有無で起動する小さなエントリーポイントへ変更する。
- `ComponentManager` を文書ロード前提に整理する。
- 必要であれば純粋クラス用の TypeScript 単体テスト環境として Vitest を追加し、`test:unit` を用意する。
- この段階では旧ツリーコードを削除せず、新基盤から参照しない状態へ近づける。

完了条件:

- 公開画面と管理画面が同じビルドで共存する。
- 管理画面では新 TypeScript が起動しない。
- 新基盤だけでページロードと既存フォームの初期化が行える。

### Phase 2: 共通グリッドとヘッダー

実施記録: [`grid-network-redesign-phase2.md`](./grid-network-redesign-phase2.md)

実装内容:

- `GridMetrics` と `GridPlaneController` を実装する。
- 公開レイアウト、二段ロゴ、常設ノード、パンくず、ページ軸線を新デザインへ置き換える。
- 16/12/4 列のレスポンシブ規則を実装する。
- ヘッダーと本文のグリッド原点、下線、接続点を一致させる。
- 左上から右下への短い初回表示演出を追加する。

完了条件:

- ヘッダーから本文末尾までグリッド線が連続して見える。
- 横幅を変えてもロゴ、文字、パンくず、接続点が重ならない。
- スマートフォンで横スクロールが発生しない。

### Phase 3: 背景信号

実施記録: [`grid-network-redesign-phase3.md`](./grid-network-redesign-phase3.md)

実装内容:

- `AmbientSignalRoutePlanner`、`AmbientSignalController`、`AmbientSignal` を実装する。
- ランダム発生、速い移動、交点での直角方向転換、ページ端での消失を実装する。
- 主進行方向を反転しない経路制約を単体テストする。
- 同時表示数、タブ非表示、低減モーション、リサイズ時の扱いを実装する。

完了条件:

- 信号がグリッド線から外れない。
- 方向転換後も主進行方向へ逆走しない。
- 長時間表示しても DOM 要素、タイマー、AnimationFrame が増え続けない。

### Phase 4: 通常ページ遷移と接続演出

実施記録: [`grid-network-redesign-phase4.md`](./grid-network-redesign-phase4.md)

実装内容:

- `LinkClassifier`、`ConnectionTerminalController`、`HandoffRoutePlanner` を実装する。
- `HandoffAnimationController`、`ScrollFollowController`、`PageTransitionController` を実装する。
- `TransitionStore` と `PageArrivalController` を実装する。
- 大きなカードには小さな接続端子を設け、端子から常設ノードまでグリッド上を移動させる。
- 長いページではドキュメント座標で移動し、画面をノードへ追従させる。
- クリック後の遷移は必ずブラウザーの通常ナビゲーションで行う。

完了条件:

- ページ遷移時に HTML 取得用の `fetch` または XHR が発生しない。
- 上部が画面外にある状態でも、ノードが不自然に画面上端から現れない。
- 外部リンク、修飾キー、新規タブ、ダウンロードを妨げない。
- 戻る・進む・連打・BFCache・JavaScript 例外時にも操作不能にならない。

### Phase 5: 主要 3 画面の移行

実装内容:

- トップページをタイトル画面風にしつつ、下部に新着情報を配置する。
- ラインナップをゲーム設定画面風の大きなメニューへ置き換える。
- タイトル詳細をグリッドに沿った情報、評価、レビュー、パッケージ構成へ置き換える。
- `public/new_design2` の見た目と操作感を TypeScript・Blade・CSS へ移植する。
- 実データ、検索条件、ページネーション、認証状態、レビュー機能を接続する。

完了条件:

- モックの主要な視覚要件を実データで再現できる。
- デスクトップとスマートフォンの両方で主要操作が完了する。
- SEO 用メタ情報とサーバー描画本文が維持される。

### Phase 6: その他の公開ページの移行

実装内容:

- フランチャイズ、メーカー、プラットフォーム、メディアミックスなどのゲーム関連一覧を移行する。
- タイムライン、新着、サイト説明、問い合わせ、プライバシー、エラー画面などを移行する。
- 共通カード、一覧、テーブル、フォーム、空状態、ページネーションをコンポーネント化する。
- ページごとの専用デザインを増やしすぎず、共通グリッド規則へ収める。

完了条件:

- すべての公開 GET ルートが新しい公開レイアウトを使用する。
- 旧ツリーノード専用 partial を参照する画面がなくなる。
- 一覧から詳細、検索から結果への通常遷移が機能する。

### Phase 7: アカウント・コミュニティ機能の移行

実装内容:

- ログイン、登録、OTP、プロフィール、マイページを移行する。
- レビュー、恐怖メーター、コメント、リアクション、フォローなどの既存 TypeScript コンポーネントを新 DOM へ接続する。
- バリデーションエラー、成功メッセージ、未ログイン導線を新デザインへ合わせる。
- POST、PATCH、DELETE のフォームやページ内 API 通信は機能単位で回帰確認する。

完了条件:

- 認証と主要な投稿・更新・削除操作が新デザイン上で完了する。
- Ajax 画面遷移用の再 hydrate がなくても全コンポーネントが起動する。
- キーボードだけでも主要操作を完了できる。

### Phase 8: 旧公開デザインの撤去

削除候補:

- `resources/ts/hgn-tree.ts`
- `resources/ts/node/**`
- 旧 Ajax 遷移用の `resources/ts/navigation/**`
- ツリー深度専用の `resources/ts/depth/**`
- ツリーの出現・消失だけに使う `resources/ts/animation/**`
- Ajax 差し替え専用の hydrate、scope、state 管理コード
- `resources/css/tree.css`
- 旧ツリーノードだけに使う公開 Blade partial
- 公開コントローラーの部分 HTML・子ノード JSON 応答分岐
- `window.Laravel` に載せている旧ナビゲーション専用設定

実装内容:

- `rg` で参照がないことを確認してから候補を一つずつ削除する。
- 汎用フォームやリアクションに利用されているコードは削除せず `site` または `components` へ整理する。
- ルート名、URL、認可、リクエスト検証、Eloquent 処理はデザイン撤去と同時に変更しない。
- 管理画面のファイルが差分に含まれていないことを確認する。

完了条件:

- 公開バンドルから `HgnTree`、Ajax ナビゲーション、ツリー深度管理がなくなる。
- 旧コードを削除しても全公開ルートと管理画面が動作する。
- 通常遷移に不要なクエリや JSON 応答分岐が残っていない。

### Phase 9: 品質確認、文書化、最終整理

実装内容:

- TypeScript 単体テスト、PHP テスト、Playwright E2E、`npm run build` を実行する。
- Playwright の固定秒数待機を、`data-page-ready` や対象要素の表示待ちへ置き換える。
- デスクトップ、モバイル、低減モーションで遷移と背景信号を確認する。
- Lighthouse またはブラウザー計測でレイアウトシフト、長時間タスク、アニメーション負荷を確認する。
- 管理画面のログイン、一覧、詳細、編集をスモーク確認する。
- 新しいフロントエンド規約を `docs/Codex/frontend-conventions.md` に作成または復元する。
- 旧方針の `docs/plan/in-page-animation-shift.md` との関係を明記し、本計画を今回の移行方針として優先する。
- `public/new_design2` は本体との視覚比較が不要になった時点で、ユーザー確認後に削除を検討する。

完了条件:

- 公開画面の E2E と管理画面スモークテストが通る。
- JavaScript 無効時でも主要本文と通常リンク・フォームが利用できる。
- アニメーションを無効化しても情報欠落がない。
- 実装とフロントエンド規約の文書が一致している。

## 9. テスト方針

### 9.1 TypeScript 単体テスト

DOM から分離できる以下を優先する。

- `GridMetrics` の座標変換と交点吸着
- `AmbientSignalRoutePlanner` の主進行方向非反転
- `HandoffRoutePlanner` の全線分が水平または垂直であること
- `LinkClassifier` のリンク種別判定
- `TransitionStore` の期限切れ判定

### 9.2 Playwright E2E

- トップからラインナップ、ラインナップから詳細への通常遷移
- スクロール後のリンクからヘッダーノードへの移動と追従
- ブラウザーの戻る・進む
- ページ内ハッシュ、外部リンク、新規タブ指定
- 検索、ページネーション、ログイン、レビュー、リアクション
- 画面幅変更後のグリッドと接続端子
- `prefers-reduced-motion: reduce`
- 管理画面ログインと代表的な CRUD 画面の表示

旧 E2E にある一律 3 秒待機は、次のような意味のある完了条件へ置き換える。

- `[data-page-ready="true"]`
- URL の変更
- 対象見出しまたはフォームの表示
- 遷移オーバーレイの非表示

### 9.3 手動確認

- 発光が文字の可読性を損なっていないか。
- 背景信号が本文より目立ちすぎないか。
- 長いページの追従スクロールが酔いや操作不能を起こさないか。
- タッチ操作で接続端子が小さすぎないか。見た目が小さい場合もリンク全体のタップ領域は十分に確保する。
- 管理画面に公開画面の CSS や JavaScript が混入していないか。

## 10. 主なリスクと対策

| リスク | 対策 |
|---|---|
| コンテンツ追加後に背景グリッドの高さが不足する | `ResizeObserver` でドキュメント領域を再計測する |
| レスポンシブ変更で接続端子が線から外れる | CSS と `GridMetrics` が同じカスタムプロパティを参照する |
| 長距離遷移が遅すぎる | 速度を上げる距離補正と最大演出時間を設ける |
| 演出失敗でページ遷移できない | `try/finally` 相当の制御と安全用タイムアウトを設ける |
| 戻る操作後にフェード状態が残る | `pageshow` で遷移状態と表示クラスを必ず初期化する |
| 背景信号が CPU を消費する | 同時数上限、タブ非表示停止、単一の描画ループ、低減モーション対応を行う |
| 既存フォームが Ajax 再 hydrate に依存する | 機能単位で全文書ロード起動へ移植し、Phase 7 完了まで旧コードを削除しない |
| 公開 CSS が管理画面へ波及する | `[data-public-app]` へスコープし、管理レイアウトへ Vite を追加しない |
| 旧コード削除時に管理機能を消す | 保護対象を差分確認し、削除は参照検索と回帰テスト後に限定する |

## 12. 着手順の結論

最初の実装単位は、全ページを一度に変更するのではなく、次の順序とする。

1. 公開画面だけで起動する新 TypeScript 基盤を用意する。
2. 共通グリッド、二段ロゴ、常設ノードを公開レイアウトへ入れる。
3. 背景信号と通常遷移用の接続演出を独立して完成させる。
4. トップ、ラインナップ、タイトル詳細の 3 画面で実データ接続まで仕上げる。
5. 残りの公開画面とコミュニティ機能を移行する。
6. 参照がなくなったことを確認して旧ツリー・Ajax 実装を削除する。
7. 管理画面を含む回帰確認と文書更新を行う。

この順序なら、管理画面に触れず、公開画面の機能を維持しながら、最終的に現行デザインと Ajax ナビゲーションを安全に破棄できる。
