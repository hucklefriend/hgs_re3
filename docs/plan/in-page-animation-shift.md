# 画面遷移アニメーションの見直し（画面内アニメーションへのシフト） 設計資料

**重要度: 高**（サイトの体験設計の方向性そのものに関わる意思決定）

## 結論（決定事項）

現状の「画面遷移そのものをアニメーションさせる」演出をやめ、**画面遷移自体は一般的なWEBアプリ同様の素直な切り替えにし、「面白さ」は画面内のマイクロアニメーションに寄せる**方向にシフトする。

まだ着手はしていない（設計・段階的移行計画がこれから）。優先度・着手時期は未確定。

## 背景・経緯

- 現行の画面遷移アニメーション（`HgnTree` のノード appear/disappear、Z軸演出など）は動きとしては面白いが、E2Eテスト（Playwright）観点で「アニメーション完了待ち」が必要になり、テストが書きづらく・壊れやすくなる要因になっていた。
- 最初は「テスト専用にアニメーションを切った版を別途用意する」案も検討したが、二重管理のコストが大きい。
- 議論の途中で、実装者自身が「本当は画面内アニメーションへのシフトをやりたいと思っていたが、踏み出す踏ん切りがつかず、やらない理由（テスト用ビルドを分ける等）を探していた」ことに気づいた。これが今回の意思決定の決め手。
- 画面遷移アニメーションは実ユーザーにとっても「毎回のナビゲーションの待ち時間」になっている面があり、テスト都合だけでなく体感速度の観点でも見直す価値がある。

## 現状の実装（参考）

画面遷移アニメーションに関わる主なファイル：

- `resources/ts/animation/` — `NodeAnimator`（ノード単位の appear/disappear 進行管理）、`AnimationScheduler`、`Easing`
- `resources/ts/navigation/navigation-controller.ts` — クリック起点のナビゲーションを scope（`full` / `children` / `node` / `external`）に応じて disappear → fetch → 差し替え → appear の順に調停している中心クラス
- `resources/ts/depth/` — `DepthSceneController` / `DepthEffectController`（Z軸演出、`playExit` → 差し替え → `playEnter`）
- ナビゲーションの scope や `data-hgn-scope` の仕組み自体（[frontend-conventions.md](../claude/frontend-conventions.md) 参照）は今回のシフト後も継続利用する想定（SPA風の部分更新の仕組みとして必要なため）。**見直すのは「遷移時に何を演出するか」であり、部分更新の仕組み自体ではない。**

## 移行の考え方（方針・未確定）

- 一気に全部書き換えるのではなく、段階的に「遷移時の演出を薄くする／なくす」→「代わりに画面内の演出を足す」を繰り返す形が現実的。
- `DepthEffectController` や `NodeAnimator` の disappear/appear は、演出をなくす場合も「差し替えのタイミング調停」自体は必要（フェッチ完了を待ってDOMを差し替える、という役割）なので、演出部分だけを段階的に無効化・簡略化していく形になりそう。
- テスト（Playwright）側は、遷移アニメーションへの依存が減ることで `waitForTimeout` 等の暫定対応を減らせるはず。移行が進んだ段階で `docs/claude/frontend-conventions.md` 側にも反映する。

## 画面内アニメーションの候補案

まだアイデア出しの段階。実装時に個別に精査する。

### マイクロインタラクション（操作フィードバック）
- お気に入り登録ボタン（`title_detail_favorite.ts`）: クリック時にアイコンがバウンド/パルスする
- レビュー・フォローのリアクション（`review_reaction.ts` / `user_relation.ts`）: いいね・フォロー時にハートやチェックマークが弾ける演出
- 怖さメーターのコメントリアクション（`fear_meter_comment_reaction.ts`）: リアクション追加時の軽いスケールアニメーション
- ネタバレ表示（`spoiler_toggle.ts`）: 開閉を高さ・不透明度のトランジションで自然に見せる

### 数値・スコア表現
- レビュー投稿・詳細表示時、総合スコアや怖さメーターの数値をカウントアップさせながら表示
- スコアバー・ゲージ（ストーリー/雰囲気/ゲーム性など）を0から現在値までアニメーションさせる

### 一覧・カード系
- ラインナップ検索結果（`lineup_search.ts`）や並び替えタブ（`sort_tabs.ts`）: 並び替え・絞り込み時にカードがFLIP的に滑らかに再配置される
- カード一覧のホバー時に軽い浮き上がり（shadow/scale）
- タイムライン（`timeline.blade.php`）: 新着イベントがリストの上からスライドインしてくる

### フォーム・入力系
- レビュー投稿フォーム（`review_form_input.ts`）、怖さメーターフォーム（`fear_meter_form_input.ts`）: バリデーションエラー時のシェイク、入力完了時のチェックマーク表示
- アバターアップロード（`avatar_upload.ts`）: プレビュー画像の切り替えをクロスフェード
- OTP入力（`otp_input.ts`）: 桁ごとの入力確定時にポップ演出

### ページ内の演出（静的ページ含む）
- About・ランディング的なページでのスクロール連動フェードイン/パララックス
- 通知・トーストの出現/消失演出

## 次のステップ（未着手）

1. 現行の画面遷移演出（Z軸演出・disappear/appear）のうち、どこまでを「薄く/なくす」対象にするか棚卸し
2. 上記候補案から優先度をつけて、影響範囲の小さいもの（例: お気に入りボタンのマイクロインタラクション）から試験的に導入
3. Playwright テストへの影響を確認しながら段階的に置き換え
