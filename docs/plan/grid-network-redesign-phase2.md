# グリッドネットワークデザイン Phase 2 実施記録

## 1. 実施結果

2026-08-13 に公開画面へ共通グリッドとヘッダーを導入した。既存の `#current-node` 以下は Phase 4 まで互換層として維持し、その外側を新しい公開シェルで包んでいる。

ヘッダー、ページ軸、パンくず、本文、フッターは同じ実測グリッド原点を参照する。列数はデスクトップ16列、タブレット12列、モバイル4列で、モバイルのみ行高を48pxから40pxへ切り替える。

## 2. グリッド基盤

### 2.1 GridMetrics

`resources/ts/site/grid/grid-metrics.ts` にDOM非依存の座標計算を追加した。

- 列数、原点、グリッド幅、行高、文書高を保持する。
- グリッド座標と文書座標を相互変換する。
- 最寄り交点へのスナップとページ左右端へのクランプを行う。
- ヘッダー到達点として左上の常設ノード座標を返す。
- 不正な列数や寸法を受け付けない。

Vitest 2.1 を開発依存へ追加し、`npm run test:unit` を追加した。`vitest.config.ts` では対象を `resources/ts/**/*.test.ts` に限定し、Playwright E2Eや旧vendorテストとの混在を防いでいる。

### 2.2 GridPlaneController

`resources/ts/site/grid/grid-plane-controller.ts` はヘッダー内の `[data-grid-frame]` を実測し、次のCSSカスタムプロパティを公開ルートへ同期する。

| プロパティ | 内容 |
|---|---|
| `--site-grid-origin-x` | ビューポート左端から共通フレーム左端までの距離 |
| `--site-grid-origin-y` | ヘッダー常設ノードのY座標 |
| `--site-grid-width` | 左右パディングを除いたグリッド幅 |
| `--site-grid-cell-width` | 実測幅を現在の列数で割ったセル幅 |

`ResizeObserver` と `resize` から更新を予約し、1フレームに同期処理を集約する。本文の伸縮に合わせてグリッド面の文書高も更新する。`dispose()` ではイベント、observer、予約済みフレームを破棄する。

## 3. 共通公開シェル

`resources/views/layout.blade.php` を次のBladeコンポーネントで構成した。

| コンポーネント | 役割 |
|---|---|
| `x-site.grid-plane` | ヘッダーから本文末尾まで続く共通グリッド面 |
| `x-site.header` | 二段ロゴ、常設ノード、接続枝、状態表示、ユーティリティ導線 |
| `x-site.breadcrumb` | ルートと現在ページ名を示すパンくず |
| `x-site.footer` | グリッド終端と運営表記 |

ページ軸にはページ種別と現在の列数を表示する。ロゴの緑ノード中心、グリッドの左端、本文・パンくず・フッターの左端は同じ原点へ揃えた。

既存ツリーは `site-main__grid` 内へそのまま配置した。デスクトップでは2列目から10列、タブレットでは2列目から10列、モバイルでは4列全幅を使い、旧ツリーの接続線アニメーションとページ内コンポーネントを維持している。

管理Blade、管理コントローラ、管理アセット、管理ルートには変更を加えていない。

## 4. 初回表示と動きの設定

`MotionPreference` が `prefers-reduced-motion` とタブ表示状態をまとめ、`PageRevealController` が通常の全文書ロード時だけ620msの対角ワイプを実行する。

- 左上から右下へ暗部が抜け、途中で信号色が短く発光する。
- `prefers-reduced-motion: reduce` または非表示タブでは演出せず、直ちにready状態へ移る。
- JavaScriptが無効でも本文は最初から表示される。
- Phase 4 のページ遷移演出とは分離し、現時点では初回到着だけを担当する。

| 検証 | 結果 |
|---|---|
